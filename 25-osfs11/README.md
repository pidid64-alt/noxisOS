# noxisOS: графический рабочий стол

Команда `desktop` реализована в **25-osfs11**, а не в учебном ядре `23-fixes`.

## Запуск исправленной версии

Нужны `gcc`, `binutils`, `nasm`, `make`, `python3` и `qemu-system-i386`.
На Debian/Ubuntu:

```sh
sudo apt install gcc binutils nasm make python3 qemu-system-x86
```

Из корня репозитория:

```sh
cd 25-osfs11
make run-desktop
```

Эта команда **пересобирает исходники**, включая пользовательские программы,
создаёт согласованные образы `build/desktop/a.img` и `build/desktop/100m.img`,
затем запускает QEMU с обоими дисками. `sudo`, монтирование образов и `mtools`
для сборки не нужны. Объектные файлы из старых коммитов не используются.

Дождись приглашения `$` в окне QEMU и введи:

```text
desktop
```

Сначала на сплошном **синем** фоне появится только надпись `Welcome to noxisOS`
(около двух секунд, любая клавиша пропускает ожидание), затем откроются два окна:
**Files** слева и **TTY** справа. Фон рабочего стола залит одним цветом — синим;
никаких зелёных, бирюзовых и красных полос больше нет.

Щёлкни по окну **Files**, чтобы передать ему фокус: клавиши Up/Down выбирают
файл, Enter открывает текстовый файл, а Enter или `q` возвращает к списку.
Окно **TTY** — настоящий терминал: ввод
попадает в него, а не в текстовую консоль позади. В текущем сеансе desktop
хранятся последние 8 непустых команд: **Up** листает к старым, **Down** — к
новым, а Down после самой новой команды восстанавливает набранный черновик.
Доступные команды:

```text
help       список команд
clear      очистить окно (алиас cls)
echo <текст>  напечатать аргументы
ver        версия (алиас version)
uptime     время работы в секундах
ls | dir   список файлов
cat <файл> показать текстовый файл
end        выключить систему (алиас poweroff)
exit       закрыть рабочий стол (алиас quit)
```

**Esc** возвращает текстовую консоль; рабочий стол можно запустить снова.
Команда `demo` запускает отдельный графический тест.

Новая версия открывает командную консоль автоматически:

- **Alt+F1** — журнал загрузки, это не командная строка;
- **Alt+F2** — первая оболочка;
- **Alt+F3** — вторая оболочка.

Во время работы графики переключение текстовых консолей отключено; сначала
выйди по Esc. Для ввода кликни в окно QEMU. Ctrl+Alt освобождает захват мыши.

## Если после `desktop` ничего не появляется

0. Обнови исходники: в старых версиях `desktop` и `demo` показывали **чёрный
   экран** в QEMU. Причина: при сохранении регистров Attribute Controller
   в порт `0x3C0` записывались индексы с нулевым битом 5 (Palette Address
   Source), а это гасит вывод; QEMU держит экран чёрным в таком состоянии
   даже при включённом режиме VBE. Теперь драйвер снова включает вывод
   (`0x3C0 <- 0x20`) сразу после сохранения регистров и после включения
   графики. После обновления обязательно `make run-desktop`, чтобы
   пересобрать ядро и образы.

1. Если нет `$`, возможно, открыта консоль журнала старой версии. Нажми Alt+F2.
2. Если виден `{desktop}`, программы нет на подключённом IDE-диске.
3. Если после запуска экран становится чёрным, убедись, что загружены **новые
   образы из `build/desktop/`**, а не старые `osfs11.iso`, `osfs11.img` или `a.img`
   из корня этой папки. Одной пересборки `kernel.bin` недостаточно.
4. ISO/дискета не содержат пользовательскую файловую систему. Вместе с ними
   обязательно подключай соответствующий **`build/desktop/100m.img` как IDE-диск**.

Старые образы в Git оставлены как исторические входные файлы; они не обновляются
автоматически при изменении C-кода. `make run-desktop` не использует их старый
код ядра и не изменяет их. Для начального IDE-диска берётся сжатый шаблон,
после чего в него устанавливаются свежие ядро, загрузчик и архив команд.

## Только образы / ISO / другая виртуальная машина

```sh
make desktop-image    # свежие дискета и IDE-диск без запуска QEMU
make desktop-iso      # дополнительно нужен genisoimage
```

Для ISO-загрузки в QEMU:

```sh
qemu-system-i386 -m 32 -cdrom build/desktop/osfs11.iso -boot d \
  -drive file=build/desktop/100m.img,format=raw,if=ide,index=0
```

Для загрузки только с IDE-диска:

```sh
qemu-system-i386 -m 32 -boot c \
  -drive file=build/desktop/100m.img,format=raw,if=ide,index=0
```

Используй BIOS/Legacy-загрузку и стандартный VGA, не UEFI. Перед пересборкой
закрой VM. Повторная сборка сохраняет остальные файлы в локальном IDE-образе,
но обновляет встроенные команды, ядро и загрузчик. Не удаляй `build/desktop`,
если там есть нужные файлы гостевой ОС; эти локальные образы не хранятся в Git.

## Проверки

```sh
make test             # отрисовка, оконный менеджер, VGA и IPC-обёртки
make test-desktop     # полная сборка + QEMU: загрузка с дискеты и с IDE
```

QEMU-тест проверяет реально отображаемые пиксели: экран приветствия, единый
синий фон, оба окна (`Files` и `TTY`), вывод команды в TTY, Up/Down-историю
(включая восстановление черновика), движение мыши и изоляцию от переключения
текстовой консоли. Затем он проверяет Esc и восстановление текстового режима,
повторный запуск desktop и цветовые полосы режима VBE 800×600 в `demo`. Тест
работает без графического окна и использует `-snapshot`, не изменяя диски.

После `make desktop-iso` можно проверить и ISO:

```sh
python3 tests/desktop_qemu_test.py --boot iso
```
